# 提交代码前检查

对当前仓库的未提交改动进行一次由用户确认驱动的提交前检查。目标是产出可审阅的风险、修复待办、复现用例、变更说明和中文提交信息。本 Skill 不直接修改业务代码、提交 Git 或阻止用户提交。

## 确认任务与 CR 范围

先以只读方式列出当前未提交文件。默认候选范围排除：

- 位于名称以 `.` 开头目录中的文件
- 位于任意 `doc` 目录中的文件
- `*.md` 文件

将剩余候选文件展示给用户，由用户多选确认本轮 CR 范围；用户可以继续排除文件。若没有候选文件，或用户未选择任何文件，直接结束，不创建交付目录或交付物。

同时询问本次检查的 task name，并枚举 `./doc/commit/` 下已有 task name，供用户选择已有名称或新增名称。用户确认 task name 和 CR 范围后，立即固定选中的文件清单；后续 CR、说明和提交信息只能基于这份清单。

使用目录 `./doc/commit/{MMDD-task name}/` 存放同一任务当天的检查记录，`MMDD` 取本次检查日期。在该目录下新建一个自然数递增的子目录，编号为现有纯数字子目录的最大值加一；没有时从 `1` 开始。

## 检查与交付物

所有交付物均写入本次递增子目录，并在会话中同时展示摘要或完整内容。

1. 将已确认的文件清单写入 `change-scope.md`。本轮生成的交付物不属于 CR 范围。
2. 开一个独立的审查 Agent，只审查已确认范围内的代码，按风险从高到低输出 `risk-table.md`。风险等级由审查 Agent 根据改动影响判断，不预设固定定义；每项风险分配稳定的风险编号，如 `R-001`，并写明等级、位置、问题、说明、影响、证据、建议动作和等级判断理由。
3. 若存在 P0 或 P1 风险，基于最小必要改动拆解修复任务，不做没有必要的兜底，输出 `todo.md`。再开一个独立 Agent 核验风险是否成立、待办是否足够，并给出可操作的页面复现用例，输出 `reproduction-cases.md`。
4. 每次都开一个独立 Agent，使用 `eli5` 或 `show-me` 对已确认范围内的改动做解释，输出 `change-explanation.md`。
5. 根据已确认范围内的改动生成准确、简洁的中文 Git commit message，输出 `commit-message.md`。
6. 汇总本轮 CR 的最终结果，输出 `cr-result.md`。报告必须包含 CR 范围、结论、风险点、风险说明、风险等级、建议解决方案和风险解决状态。每个风险引用其风险编号；没有风险时明确记录“无风险”。

初次交付时，未处理风险的状态为“待用户决策”。用户要求修复时，将对应风险更新为“待修复”；修复后的复查确认风险消失时更新为“已修复”，仍然存在时更新为“未解决”。用户确认无需修复时，更新为“已接受风险”。P0/P1 待办应可独立执行；复现用例应包含前置条件、操作步骤和预期结果。若执行环境无法使用所要求的独立 Agent 或 Skill，明确告知用户并等待其决定，不要悄然降级执行。

## 检查后的确认循环

交付物发送给用户后，等待用户决定后续动作：

- 用户要求修复：先确认修复方案，将本轮 `cr-result.md` 中对应风险更新为“待修复”，再实施；修复完成后重新执行本 Skill，并根据复查结果将原风险更新为“已修复”或“未解决”。
- 用户确认无需修复：将本轮 `cr-result.md` 中未处理风险更新为“已接受风险”，本轮检查结束。

不要因检查发现的问题自行修改代码、提交 Git 或无限循环检查。每次重新检查都必须由用户确认触发。
